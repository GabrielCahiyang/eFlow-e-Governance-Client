## Target information architecture and components

Views share project identity, common filters/chips, visible task count, task opening, async feedback, and user-specific visual preferences. View-specific controls remain contextual: Board lanes, Gantt range/zoom, Calendar date/mode, Dashboard presentation, Offices grouping. All navigate the same canonical task ID. The inspector provides Overview, Activity, Discussion, Evidence, Review, Team, Subtasks, Budget, and Dependencies only when useful and permitted; avoid nine compulsory tabs on small screens. Domain-specific sections compose existing features, with neutral panel/focus primitives from Phase 8B.

Add an explicit task-inspector feature public API with a compatibility re-export at the current drawer path until repository search shows no consumers. Its opener receives task ID and origin/return-focus context; authenticated canonical data and existing capability selectors determine actions. A generic `canManage` flag must never imply staffing, review, budget, or access authority.

## Data/API effect and authority

**No database/RLS/business-rule changes.** Preserve canonical tasks/subtasks/workflow facts and public service payloads/returns. Keep project access separate from account role; observers/Admin oversight remain read-only, Head acts within own Office, and Task Lead organizes only their own eligible task team/subtasks. G2 must specifically permit the intended contributor-team delta without allowing lead replacement, cross-Office staffing, or blockers bypass; that correction is separately reviewed and tested outside this UI phase. Proposed unresolved Phase 6.5 Office identity cannot staff or execute tasks until linked canonically.

Local saved zoom/range/filter/section preferences are personal presentation state. Shared saved views, cross-device preference storage, inspector section data lacking a current source, or new aggregation endpoints require a separate persistence/API/RLS proposal. Do not make client visibility a replacement for server authorization.

## States and safety

Each section and mutation has idle, loading, success, failure, retry, empty, and disabled behavior. Keep shell/context visible while a section loads; separate no evidence/no events/no tasks from a denied or failed request. Retry a failed section/save without duplicating prior successful writes. Show exact blocker/capability explanations and link to authorized review, Office, or readiness resolution. Do not represent completed/for-review task mutation failures as successfully saved.

Level 1 presentation/ordinary inline edits are direct; Level 2 team/access/responsibility/material schedule edits show impact; Level 3 authority-sensitive/destructive actions retain existing confirmation/blockers. Guard explicit multi-field drafts on close, project/task switch, route change, and browser back; do not silently autosave team/review/evidence forms. Pending operations disable only conflicting actions. Realtime revocation/deletion closes stale mutation affordances and explains the change without leaking restricted data.

At 390px use full-width inspectors with scroll-contained sections, sticky safe controls, focus trap/return, accessible tabs/menus and Escape semantics. Board and Gantt have non-drag alternatives; graphs/charts have textual values; Calendar status is not color-only; reduced motion, labels/error associations, keyboard navigation and no document overflow are release gates.
