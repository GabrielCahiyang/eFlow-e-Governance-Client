## Final behavior and boundaries

Polling and focus refresh continue while drafts are dirty. Transient read failure preserves the last snapshot and open draft, presents Retry and disables fresh-authority-dependent actions. Explicit RPC access/auth denial clears protected tree/people display and unmounts its editor; only scoped draft fields and request terms remain quarantined in this tab. An authorized fresh read is required before recovery. Plain Error denial strings used by existing compatibility callers remain recognized alongside structured RPC codes; generic network errors do not count as denial.

Per-tab sessionStorage keys contain actor/project/root/item/mode and baseline revision. Records contain only whitelisted form fields, baseline field values/IDs, immutable scalar request terms/ID arrays, optional impact fingerprint and request certainty metadata. No whole snapshots, credentials, File objects, evidence payloads or signed-path objects are stored. Unknown keys and nested command payloads are rejected/stripped; malformed or foreign records are ignored. Storage failure leaves the in-memory editor usable and displays its recovery limitation. Storage data never grants authority.

Recovery restores the original baseline revision and created/request IDs after fresh capability context verification. Stale recovered drafts are identified and cannot start a new write with stale terms. An uncertain request may perform an explicit identical receipt retry through the existing server checks. A known stale/revoked request remains known blocked after reload; it is not reclassified as uncertain. Pending requests are persisted before dispatch, including untouched review/delete forms. No automatic save/retry occurs.

Close, existing section changes and Main Table collapse use the shared guard. Actor/root/item/mode identity invalidates old discard decisions. Pending writes block dismissal. Accepted discard removes only the current scoped revision; successful save removes its draft before owner refresh. Confirmed save plus failed refresh cannot duplicate a write. Actor changes isolate/purge other actors' stored entries; logout clears entries when the tree owner observes it. A different actor cannot recover old entries even if storage remains after unmount. Late reads and receipts cannot replace a new actor/root/item.
