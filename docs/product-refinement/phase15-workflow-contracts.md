`useProposalDraftPersistence` serializes autosave and explicit save requests. A completed older write cannot mark newer edits saved; failed saves retain dirty review and offer retry. Current section navigation is local presentation only and is not a new resumable storage contract. Saved draft dismissal is prompt-free; changed review is guarded, and an active write cannot be discarded mid-request.

Existing initial collaboration-draft creation does not expose an idempotent batch contract. This phase preserves that service lifecycle and does not claim recoverability of an unknown initial create/source-upload outcome. Draft autosave retries target the known draft ID. Existing-project import has its separate batch identity and safe retry contract. Consolidating those lifecycles remains separate work.

Official readiness keys inspected in Phase 7 SQL are structure, dates, budget, work, schedule, invitations, responsibilities and staffing; Phase 6.5 adds office_identity. Unknown keys get their server explanation without a guessed destination. Closeout task/subtask blockers keep canonical task-inspector handoffs; cash blockers link to Budget Overview and governance blockers to Approval Status. Missing RPC errors explain administrator installation rather than enabling repeated futile retries.

G2 shared-project Task Lead staffing remains gated by the existing task trigger. G4 personal recipient invitations and bulk PDS metadata remain unsupported. No global AI/PDS/governance sidebar destinations or approval shortcuts were added. Tests use synthetic transport fixtures against the live frontend and isolated server tests, not deployed RLS or real AI/email services.
