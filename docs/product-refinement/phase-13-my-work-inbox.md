## Target information architecture

My Work is global/personal, not an Add to workspace item. Sections/filters: Assigned to me, Leading, Due today, Due this week, Overdue, Recently completed; optionally Needs my review links to Inbox. Use available project/Office labels for context without revealing inaccessible records. Task/subtask selection opens the shared inspector or existing subtask execution surface with origin/return context.

Inbox categories: Needs action, Updates, Mentions, Invitations. Needs action may normalize **discovery items** from existing task/subtask review, workplan/governance, Head financial authorization, Office invitation and readiness sources. Each item's canonical owner performs the action. Introduce no universal Approve button, no role conflation, and no inferred unread/actionable equivalence. Mentions/Invitations are shown only when reliable existing sources cover them; missing feeds are explicit gated proposals, not fabricated categories.

4. **Build Needs action as adapters, not a new workflow engine.** Add focused read/discovery adapters in a new `personal-work`/`action-center` feature, with stable `source:entity` keys, source-specific counts, status, loading and errors. ## Authority, states and safety

Project access is distinct from account role. Task Lead can manage their own eligible contributors/subtasks; Head appoints Leads and operates own Office; Lead Office does not select another Office's people. Admin gains no operational/review/financial authority from global Inbox visibility. Head authorization and Accounting Staff release/settlement/journal actions retain separate owners and controls. Pending project-local Office identity can create a discovery/resolution item but cannot start staffing/execution. G2 prevents shared-project UI from promising a Lead mutation current SQL denies.

Idle shows personal context and source-qualified counts; loading uses row skeletons with stable selection; success names the delegated operation and refreshes its source; failure preserves the current draft and other sources; retry targets only failed reads/writes; empty distinguishes a clear queue, filtered results, inaccessible sources, and unsupported categories; disabled actions explain access, lifecycle, identity or existing blockers. Never convert an unread update into an actionable approval.

Presentation filtering is nonmutating. Read-state changes are low risk and show accurate completion/error when the supported contract allows; use no confirmation for every mark-read. Team/Office/access/material workflow changes retain impact confirmation; irreversible review/financial/governance actions retain existing strong confirmation and audit behavior. Dirty inspector/team/review/evidence forms guard close, selection, navigation, project switch and browser back. Stale rows must recheck canonical eligibility before acting; failed refresh cannot recreate an already accepted mutation.

At 390px show compact rows and full-width details, keep global discovery reachable, collapse secondary context, and avoid document overflow. Lists/tabs/filters have semantic names and keyboard navigation; selected row, badges, source errors and async announcements work without color. Preserve focus after returning from a workflow and never announce sensitive hidden content.
