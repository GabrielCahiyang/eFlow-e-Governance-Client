### Server behavior and atomic invariant

Four new private functions: `eflow_r7.lock_completion(uuid)`, `lock_completion_write()`, `require_completed_descendants(uuid,uuid)`, and `check_completion_commit()`. Anonymous/authenticated/service roles receive no direct table/helper access. All existing RLS policies, table/view privileges, function signatures, ACLs, definer/search-path properties and bodies are catalog-compared; only six existing entry-point bodies receive the exact reviewed lock preamble.

The approval entry points acquire the common serialization row before their existing task/node row locks. R7 commands retain their existing project-before-root lock order. Root/node/formal-attempt insertion, deletion, reparenting and updates share that row lock, held until transaction end. The version is actually updated, ensuring old Repeatable Read snapshots fail serialization when a concurrent descendant writer committed, rather than inspecting stale completed rows. Changes under other roots use separate rows.

A BEFORE consistency check gives an actionable descendant title/ID and retry hint when approval is attempted. A **DEFERRABLE INITIALLY DEFERRED constraint trigger** rechecks the transaction's approval targets at commit, so a later change in the same transaction cannot invalidate an earlier approval write. Every later relevant write queues the check too, preserving the invariant if the caller sets constraints IMMEDIATE. Both trigger classes are ENABLE ALWAYS: trusted repair using replication-role mode still participates in serialization and final consistency; ordinary workflow/permissions remain unchanged. A DBA deliberately disabling these new triggers is outside a database-trigger guarantee and is not tested or authorized.

Office descendants must be `completed`, `is_completed=true`, and, when a formal latest attempt is bound, that same node/task attempt must still be approved. Existing legacy completed rows without formal attempts retain their original completed-state contract; there is no evidence/authorship backfill. All canonical descendants remain required, including standalone work and UI-hidden descendants. No new cancellation/optional-child rules were introduced.

Approved-state inserts and transitions are checked; historical already-completed rows are not automatically re-decided. A trusted repair in a **later transaction after approval committed** does not revoke or rewrite that historical approval.
