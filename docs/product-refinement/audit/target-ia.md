# Target IA freeze

Freeze date: 6 October 2026. The following constraints guide later implementation; current screens remain reachable until a replacement proves parity. [Every current surface maps here](current-to-target.md). Gates remain open for capabilities not established by current source.

| Layer / destination | Reason for global or contextual placement | Scope / release condition |
| --- | --- | --- |
| Home | Account landing, Office overview and actionable summaries span projects | Head Office-wide overview remains separate from personal tasks; other roles keep suitable defaults until equivalent landing exists |
| My Work | Personal assigned, led, subtask, deadline and history discovery spans projects | Derived canonical records; not a workspace-created resource; existing routes/lead conditions preserved |
| Inbox | Action discovery spans task, invitation, governance and financial contexts | G4 defines independent feed/entity/action capabilities before consolidation; notification read does not approve work |
| Search | Cross-context retrieval cannot be constrained to one project view | G3 requires data-source/scope/query decisions; no cross-Office search or new backend assumed |
| Workspaces | Project portfolios and Office people/shared content need a context layer | Existing Office label can remain context; genuine selectable workspaces, folders, favorites and shared dashboards require G3 |
| Accounting | Releases, settlement, journal and ledgers span projects and have dedicated duties | Five permission keys and financial capability checks retained; never converted into Head management |
| Admin Center | Account/org/permission/audit/settings/backup support spans product | Operational superuser excluded; explicit individual grants retained; A01 entry/content mismatch corrected separately |
| Help and Profile | Own-account support/settings/session functions span product | Existing topbar caller, tours, onboarding, Settings tabs and logout retained |
| Project views | Main table, Board, Gantt, Calendar, Overview, timeline, Office, dashboard and optional registers refer to one project | Preserve project/page/view query and filters; optional view conditions and Board return |
| Task/project inspector and contextual people/governance/finance | Actions concern a selected record and independently authorized scope | Evidence, team, dependencies, funding, PDS, identity resolution and lifecycle keep their service/state machines |

Target labels do not create a workspace entity, shared dashboard store, favorites table, global search API or unified approval operation. No surface is removed in 8A. `Keep`, `Combine`, `Convert-to-view` and `Move-contextually` describe later placement with explicit route/action retention, not permission grants. No current row requires `Retire-visually` without replacement evidence.

Approved implementation constraints derive from the user's phase request and existing compatibility rules. New storage models, route retirement and the intended-versus-enforced G2 authority change remain future decisions, not user approvals inferred from this audit.
