# Mutation registry and safety handoff

Use [the per-call register](inventory/mutations.json) for stable IDs, file/line, nearest handler, feature owner, target, actor/scope/permission, risk, server validation, audit effect, confirmation, undo, blockers, async states, dirty handling, evidence status and next inspection. [Server routes](inventory/server-routes.json) and [SQL declarations](inventory/sql-functions.json) support tracing dynamic boundaries. Every indexed candidate has all fields; unknown fields remain explicitly unresolved with Phase 17 + feature ownership.

The TypeScript AST scanner inventories named write/handler calls, Supabase/storage/auth/local writes and explicit write requests throughout `src/`; JSX surface consumers and all Python write-route decorators are separately indexed. It conservatively retains read RPCs, signed-URL helpers, aliases, DOM/local helpers and dormant prototypes. It does not prove runtime reachability or capture arbitrary dynamically named callbacks. This is a source triage register, **not a claim that every runtime mutation has been fully certified**. Phase 17 must trace unresolved callbacks, payloads and last effective server definitions before declaring complete mutation safety. Raw method names never determine authoritative eligibility or a final risk level.

Risk freeze: L1 reversible inline/local save with immediate feedback; L2 important record effects with an impact summary where warranted; L3 destructive, financial, privacy or authority-sensitive operations with explicit confirmation and server blockers. Classification follows payload/effect rather than button wording. No generic undo exists merely because a row is tagged L1.

Dirty strategy freeze: inline autosave gets no blanket discard prompt. Multi-field forms need explicit close/back/project-switch/navigation decisions. The existing temporary-operation lock is not that guard. Phase 6.5 LocalOfficeDialog already implements local discard; that does not establish a global pattern. Server blockers must be rechecked at commit; presentation never authorizes a stale action. Important async actions must distinguish saved-but-refresh-failed and saved-but-delivery-failed from an uncommitted draft.
