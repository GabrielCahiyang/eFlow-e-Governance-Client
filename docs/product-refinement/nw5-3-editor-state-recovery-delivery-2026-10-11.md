## Final behavior and preserved contracts

- Untouched forms are clean. Dirty equality uses only applicable fields for each mode; contributor membership is a set, sibling order remains positional, and personal review compares the actual approval/return decision. Due dates, standalone execution mode and notes now participate where applicable.
- Baseline revision and created-node UUID stay stable across current snapshot updates. First send freezes the request ID, command, payload including copied arrays, revision and optional impact fingerprint. Unknown-result retry sends the same object and identical terms, including after a fresh revision advances. No automatic retry or checked-to-unchecked fallback is added.
- Preparation failure before sending is a confirmed non-send. Explicit server rejection/rollback or missing RPC on a first attempt is a confirmed non-commit and permits an explicit new attempt with a new request UUID. After any uncertain result, a rejected lookup cannot establish whether the original operation committed: retain the original frozen request and navigation protection. After an authoritative denial or stale lookup, only a newly verified read can permit another exact receipt lookup. No old request terms are rewritten. Serialization/revision failure and authoritative permission denial are separate blocking outcomes. Connection, untyped and missing/malformed receipt failures remain uncertain.
- An uncertain request is navigation-guarded even if its visible form fields were untouched. Fields are locked after an uncertain send. Exact receipt lookup may remain available after completion/deletion removes mutation eligibility, provided the current actor/root/project/Office/kind read presentation is verified and the view is writable. The server still checks current read access, identical receipt terms and current mutation authority if no receipt exists; this grants no new mutation authority.
- A confirmed save is recorded before notifying the owner. A synchronous or asynchronous owner/refresh failure produces `committed_refresh_failed`, leaves the editor clean and offers Close. It cannot re-enable submission or duplicate the committed operation. Late receipts/errors do not notify a different actor or an unmounted owner.
- Open non-staffing editors use current NW2 action capability for create, details, move, delete, order, execution, submission and review. Move destinations use current destination creation capability before the existing depth/cycle/status filtering. Existing staffing delegation retains its independently verified appointment/contributor capabilities. No original `edit.node.can_appoint` or legacy mutation flags authorize an open editor.
- Existing form layout, callers, payload allowlists, ordinary/checked RPC signatures, success snapshot return, optional fingerprint semantics, eligibility, Office boundaries, manual progress behavior, hierarchy limits and children-first deletion remain. The shared navigation/draft hooks and `useWorkTree` were read but not changed.

Preserve own eligible Office Subitem Lead first, then eligible parent/ancestor Leads, Task Lead and responsible Head, skipping the submitter.
