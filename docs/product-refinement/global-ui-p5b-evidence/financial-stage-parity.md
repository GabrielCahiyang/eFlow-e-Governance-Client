Source service comparison: `budgetService.ts` maps Accounting settlement to `settle_accounting_liquidation`; late Head authorization to `decide_petty_cash_liquidation`; contextual Lead endorsement to `decide_petty_cash_liquidation_leader_review`. These are distinct stages. Receipt URLs still use the existing 600-second signed URL operation. No service signature, return shape, payload or backend endpoint changed.

Migration evidence read directly: `20261003000004_simplified_roles_and_office_authority.sql` preserves independent Accounting settlement and the late Head authorization trigger; `20260831000002_cash_release_schedule_override.sql` retains the release compatibility wrapper; `20261010175812_nested_work_checked_confirmation.sql` adds nested-work checked confirmation/impact locking. No migration file or hosted history was edited or applied.

P5b changes composition: one parent budget/journal owner is supplied to embedded Budget; standalone Head Budget owns its current hooks. Actor/role/Office changes remount the feature owner, and existing FY/request-generation protections remain. The existing embedded `view`/`fy` route/history writer is preserved. No network-performance claim is inferred merely from removing a source-level duplicate owner; synthetic browser counts verify one initial owner read in the tested scenario.
