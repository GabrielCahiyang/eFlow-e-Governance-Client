# Phase 18 local acceptance and deployment gates

This implementation preserves the Phase 8A route/action map and the Phase 17 mutation reviews. Browser fixtures use synthetic records and intercept backend traffic; screenshots and timing records are local web evidence, not deployed authorization certification.

| Gate | Owner | Acceptance |
| --- | --- | --- |
| Browser correctness | Web maintainer | All 115 selected critical cases must pass in each of Chromium, Firefox and WebKit (345 cases), without skips or flaky retries. `npm run test:e2e:release` enforces nonempty, complete passing reports, baseline auditing disabled, `forbidOnly`, and zero retries. The selection includes retained Phases 1–7 smoke, navigation, personal work and Phases 10–18. |
| Automated accessibility | Web maintainer | No serious/critical WCAG A/AA findings on the four audited role workspaces, Office Team, Reports, Inbox, task inspector and empty project state across 320/390/768/1024/1440 CSS px. No document overflow; mobile navigation focus returns after Escape. |
| Draft/focus compatibility | Feature owners | Dirty discussion survives 320/390/768 rotation and forced colors; Keep editing retains text; Discard returns focus. Existing planning, account, staffing, financial and governance regressions remain mandatory. |
| Comparable performance | Web maintainer | Three production-preview runs, same machine/browser/synthetic network profile. For 100 and 1,000 tasks, comparable route/filter medians may not exceed baseline medians by more than 10%. Journal must use one scoped read rather than two. The final filtering comparison fails; [the recorded issue](phase18-performance-issue.md) needs a fix or an explicit release decision. This is a local regression guard, not a business SLA. |
| Scale and rendering profile | Product and web maintainers | The 5,000-task baseline timed out. No baseline median or improvement percentage is valid at that size. Approve a supported task count using actual usage; production long-task/React-profiler/peak-memory and WAN measurements remain required before a large-scale performance claim. |
| Bundle size | Web maintainer/release owner | Preserve actual warning logs and payload measurements. The measured static public-contract cycles are grouped while view exports remain deferred. A large shared chunk remains; zero cycle warnings does not certify load speed or approve its size for deployment. |
| Assistive technology | Accessibility owner | NVDA on Windows and VoiceOver/Safari must be tested in their actual environments. Automated axe and keyboard checks do not certify screen-reader behavior or native Safari. 640 CSS px tests reflow corresponding to a 1280px window at 200%; they are not an OS browser-zoom test. |
| Authority and receipts | Backend/feature owners | Keep G2, Phase 6.5 deployment, audit persistence and all unresolved Phase 17 registry release claims owned and blocked until independently verified. Isolated SQL/browser fixtures do not prove live RLS. |
| Rollout and rollback | Release operator | Identify actual deployed revision/artifact and rehearse restoration in the chosen deployment system. Local baseline artifact restoration is recorded separately. No deploy, migration, feature flag or remote push is performed by this UI phase. |
| Native alignment | Mobile owner | Mobile A/B requires the actual native repository and deployed API receipts. The web browser matrix does not complete those tracks. |

The checked-in CI workflow uses a synthetic public client configuration and a production preview. It is prepared locally; a hosted CI run is not claimed until its receipt exists. Deploy with the repository's chosen mechanism and independent revertible commits; retain previous hashed assets and the matching `eflow-view-modules.json` for the rollback window. Do not revert database migrations or widen permissions as a UI rollback.

Pinned `@axe-core/playwright` 4.13.0 follows [Playwright's accessibility guidance](https://playwright.dev/docs/accessibility-testing). The browser projects follow [Playwright's project configuration](https://playwright.dev/docs/test-projects). Axe findings are retained; checks do not suppress rules or exclude failing product elements.
