## Target responsive IA and component work

- Desktop: global rail/navigation plus workspace content panel, project view tabs, contained large tables and side inspectors.
- Tablet: compressed/collapsible workspace panel, wrapped toolbars, visible view switcher and comfortable inspector width; no overlapping floating actions.
- Mobile web: primary Home, My Work, Projects, Inbox and More where each is authorized. More holds applicable Accounting/Admin, workspace selection and support/profile entries. Admin's operational restrictions remain: an unavailable Projects destination must not be shown just to match the conceptual mobile list.
- Project mobile layouts may use list/calendar agenda/compact board variants over the same canonical records; keep explicit navigation back to Main Table. Gantt complexity can use a contained scroll view or a justified simplified representation with the equivalent supported actions reachable.
- Inspectors/dialogs fill the available height on narrow screens, keep a reachable footer, preserve dirty forms through keyboard/viewport changes and restore focus/context on return. Use shared scroll/layer/motion tokens rather than per-feature z-index patches.

6. **Measured rendering/data optimization.** Eliminate demonstrated duplicate journal/controller subscriptions, excessive refreshes and repeated expensive selectors with one scoped data owner or supported cache keyed by authenticated user, Office/project and fiscal year. ## Measurement and acceptance budgets

At kickoff agree documented hardware/network/data profiles, collect at least three reproducible runs and use medians plus outliers. Use production builds for performance claims. Suggested fixtures: 100, 1,000 and 5,000 tasks, realistic groups/subitems/long text, 500 audit events and populated fiscal-year journal; select the supported upper bound from actual usage rather than asserting arbitrary scale.

Record initial/authorized route payload and chunk sizes, route ready/inspector open/filter-to-paint times, request/channel count, long tasks, React render count and peak DOM/memory. Proposed initial regression guard: no more than 10% worsening of comparable median route/interaction metrics and no unexpected extra duplicate scoped fetch/channel; ratify thresholds after baseline measurement. Set absolute user-facing latency targets from that measured environment before optimization, and report unmet targets as release issues rather than redefining them after a failure. Browser correctness/security gates are absolute, independent of performance tradeoffs.

Virtualization is conditional on measured render/DOM bottlenecks and a documented supported scale. Code splitting is conditional on actual chunk/route behavior. Resolve known circular-export warnings or record each justified residual with exact path, effect, owner and accepted release decision; do the same for large chunks. Warnings are not test failure, but silence alone is not proof of improvement.

## API, authority and safety

**No database/RLS/business-rule changes.** Preserve existing API/service return contracts, task lifecycle, review/finalization, invitation security, Office staffing and financial rules. Cache/coalescing changes are internal adapters with tested invalidation and per-user scope; new paging/count/idempotency endpoints or schema/index changes require separate capability review under the owning phase. Phase 6.5 migrations remain separate and are neither redesigned nor reverted as UI rollback.

Responsive route aliases and optimized rendering must retain Head own-Office appointments, delegated own-task Task Lead contributor/subtask authority, no cross-Office staffing, observer read-only behavior and no Admin operational elevation. The Task Lead shared-project authority discrepancy must be resolved through its separately scoped authoritative correction before the affected release path is claimed complete. Head authorizes while independent Accounting executes; AI remains advisory; raw PDS/tokens/signed financial URLs cannot enter public snapshots, logs or shared caches.

Level 1 low-risk edits retain direct/blur save and optional feasible Undo; Level 2 staffing/access/material-plan changes retain impact confirmation; Level 3 destructive/authority/financial final actions retain strong confirmation/blockers. Optimization must not drop one-in-flight protection, retries or dirty guards. Unsaved inspectors survive viewport changes; close/back/route/project switches invoke Keep editing/Discard; saved autosaves do not produce spurious warnings.

Every audited route includes initial/refresh loading, empty/filter-empty, success, actionable failure and retry. Chunk/read failure offers retry with retained route/draft where safe; ambiguous mutation failure first verifies the result. Disabled actions have visible keyboard/touch-readable reasons and permitted resolution routes. Skeletons must not announce constantly; errors have labels/association and meaningful focus behavior. Inspectors remain usable when reduced motion, forced colors, keyboard-only navigation or zoom changes are active.

## Rollback and definition of done

Capture the exact prior deploy/revision and rehearse restoring it in a test environment; preserve all canonical records, audit and existing migrations. Use independent rendering/navigation/optimization commits so a regression can be reverted without undoing other phases. If additive data contracts were separately introduced, maintain backward compatibility for the UI rollback window. Release documentation must state which verified slice is canonical and retain supported old-link adapters until migration is proven.

Done means all canonical routes/actions retain the authority matrix; responsive/a11y/visual/cross-browser and critical E2E gates pass without critical skips; performance measurements meet agreed budgets or have an explicit release decision; cycle/chunk findings are addressed or individually accepted; client-secret checks pass; docs/tours match shipped behavior; rollback is rehearsed. Out of scope: native app redesign (Mobile A/B owns it), new feature destinations, policy/schema rewrites, benchmark claims without evidence, forced virtualization, dependency churn unrelated to findings and new financial/PDS/AI capabilities.
