The main simplification is to remove repeated destination controls while preserving every distinct operation. The previous context-isolation correction is present and should remain. The largest remaining problems are nested Admin navigation, duplicated Accounting destination/settlement surfaces, retained My Work routes without an active context item, and the same display state being managed by route helpers and component-local selectors.

## 1. Decision rules and audit limits

**One primary navigation context, one authoritative destination selector, and local filters only for data within that destination.** A contextual link from a record to its evidence, membership, journal or review is useful; it is not a second general navigation menu. Tabs for parts of one inspector or journal record are also legitimate. A date filter, fiscal year, search, loaded-record scope or sort does not become a destination merely because it appears as a button.

Removed means removing a redundant control or wrapper, not deleting the business component, route, service, data or history. Merged means sharing presentation or navigation ownership; it never combines decision authorities. Relocated means making an existing capability reachable from its correct context. Redesigned means reducing layout/state clutter while retaining its contract. Preserved means the distinction or existing correction is intentional.

This is a source-level audit. No new live sessions, hosted database reads, visual screenshots, mutation tests, migrations or deployments were performed for this audit. Source proves composition and state ownership; it does not prove current hosted installation, computed contrast or runtime race behavior. Existing test files are verification targets, not newly passing acceptance evidence. Local Graphify was used as a bounded navigation aid, then source and relevant migration/contracts were inspected. Its extraction warnings are not permission evidence.

No database/API change is proposed. The only future hosted target remains ixnfphgjyelhckjwjkdv, with live migration timestamps preserved. Any genuinely missing backend capability must be separately diagnosed and reviewed, rather than added to this presentation refactor.

## 3. Proposed navigation architecture

Keep the existing route owner. Extend the navigation feature's authorized presentation records into one small destination descriptor consumed by desktop rail, mobile drawer, collapsed/standalone fallback and authorized search. Do not add a separate activePrimary, activeCategory or global selectedQueue state.

Flow: **URL + current role/capabilities → canonical destination descriptor → primary group + one selector host → selected content outlet → local filters/record Inspector.** Existing navigationGuard and navigationHistory perform accepted transitions. Preferences remember accepted destinations; they do not override a URL, fresh authorization or a current submission/version.
