## Behavior implemented and preserved

WorkHierarchy loads nothing and writes nothing. It accepts one authorized snapshot and controlled collapse/focus/callbacks. Both layouts share NW6.1 canonical traversal and one NW2 capability adapter. Native desktop columns are Subitem, Lead, Contributors, Status, Due, Progress, Actions; no treegrid roles are introduced. Mobile uses paths and at most three indent levels. Only the active composition is mounted, so the inactive layout contributes no focus targets or accessibility nodes. Shared WorkPeopleSummary, StatusPill and existing progress/date primitives preserve explicit Lead, distinct Contributor count, historical names, readable status text and progress values.

Each item has one labelled ActionMenu. Legacy can_manage/can_order/can_work flags cannot grant hierarchy actions. Read-only authorized Open/Activity remains available; execution locks affect personal execution/submission through the adapter. Office Open uses onOpenNode for evidence handoff and Review uses onRequestAction('review', node.id), leaving evidence/review ownership with the caller. Office execution is not routed into personal progress/submission. Existing WorkTree Office callback implementations and personal editors remain unchanged pending NW6.3 integration.

Reorder children always uses the selected parent's order_children: root action sends callback nodeId undefined (existing serializer parent:null), node action sends node.id (serializer parent:node.id). A child capability never grants parent/root sibling ordering. No order array is assembled from visible rows. Regression coverage uses the existing editor baseline/serializer to prove complete collapsed child IDs and exact parent payloads. Root Choose people sends the existing staffing mode with no node ID; the canonical dialog chooses contributors/appointment commands through its existing independent capabilities.

useWorkTree now supplies the explicit controller and both synchronous duplicate-send protection and render-state pending. Actor/root switches immediately conceal previous data/revoke freshness, before the new read effect; stale callbacks cannot send through the old owner, and old request completion cannot clear a new owner's pending state. Transient refresh failures retain verified display/drafts but revoke mutation access. Denials clear protected display. A response without service-verified current identity cannot restore authority, overwrite verified display or unlock draft recovery. The hook uses the adapter's existing WeakMap bookkeeping rather than another identity or business-rule source. Quiet verified in-flight reads retain the existing save/read race contract; save supersedes earlier refreshes. Unknown result retries retain the exact caller-owned request.

Supplied WorkTree/WorkRootOwner controllers start zero additional tree pollers; omitted props retain standalone connected owners. Pending mutation locks preserve authorized read-only Office Open/evidence callbacks. Final review restored this pre-existing read-button behavior after an overly broad pending lock; the pending regression now asserts both disabled mutation triggers and enabled evidence handoff with zero writes. The actual Main Table still uses its previous owner arrangement until NW6.3. WorkStaffingDialog keeps its scoped draft, one controller.save submission, authoritative impact/confirmation, exact uncertain retry and confirmed-receipt onChanged behavior.
